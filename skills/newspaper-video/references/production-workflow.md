# 制作流程与开工条件（1.4）

## 1. 入口：先确认，再启动

必须获得主语言、字幕模式和语言、配音工具的真实用户选择。已有本次明确回答直接沿用；缺项只询问缺项。主语言覆盖口播、画面自制文案和第三方材料的首选语言；字幕可 none/single/dual，不能从口播语言推断字幕。配音选项包括 Mac 系统、Windows 系统、VoiceStudio（需额外下载安装；已安装则检查实际版本/英语或目标语音色）；不得自动替用户选系统声。工具选择后再展示真实可用音色、授权范围及试音，不用虚构音色名。不明确时不得初始化制作工程、配音、动画或渲染；可收集需求和检查工具库存。

## 2. 调研 → 双语审稿包 → 用户确认

入口完整后在独立审稿目录准备资料，不初始化制作工程。交付每镜：ID、预计时长、主语言口播、中文/英文对照译文、画面文案中英对照、具体图片主体与来源、图像间关系、动画/声音意图、事实来源与不确定性。审稿翻译不自动进入成片或字幕。

叙事先以本期问题/冲突/结果预告作钩子，长度按内容决定，常见 5–20 秒；再用短 IP 识别过渡，随后进入主体，结尾自然回扣及频道引导。固定水印可从开头存在，不等于开头先念品牌。禁止为了凑时长机械拉伸、截断口播。

口播交付前逐句审核：每句都应对观众提供事实、解释、转折或观点。删除“我需要核实/这里应该放/我们不能直接证明/先看证据到哪/接下来写”等制作过程、自我指令和编辑备忘。必要事实限定写成自然观众语言，例如“Prosecutors have not announced charges.”；禁止把整段方法论防御当作叙事。提示词/制作说明/来源备忘存独立字段，TTS 只读取批准的 narration 字段。关键词扫描只提示，必须通读所有句子；不声称检测器能证明没有思考过程泄漏。

用户明确确认脚本版本后，将原消息或引用及脚本 SHA-256 记入 production-brief.json。反馈修改稿件后旧哈希自动失效，重新确认。禁止 Agent 自填“已批准”。批准前不做新片配音/动画/渲染，Skill 本身的单元测试可使用明确标记的测试夹具。

### 观众成稿与内部核查的边界

口播写作前完成事实判断。逐句问：这句话是在向观众讲事件，还是在回应用户要求、解释Agent为何不采用某观点？后一类移到内部审稿记录并删除口播，不换一种措辞继续辩解。常见问题包括“这并不等于”“不能据此认定”“日程本身不证明”“合影不是协议”等无叙事必要的纠偏，不能当作默认过渡或结尾。

未证实又不影响主线的说法直接省略；保留已核实的积极事实，或在明确分析段自然使用“可能/如果”。必要报道归属或指控限定紧邻具体主张，仅用最短准确表述。省略辩解不等于把未证实内容改成肯定句。事实、分析、创作说明在源数据中分字段；成片不展示内部审稿争论。

例如“G20日程不等于确认另一次双边会谈”删除，叙事需要时只说“外交日程还将延续到12月G20”，不虚构双边安排。“同台不构成三方谈判峰会”删除，只陈述已核实的同框及各场会谈。用户明确同意“按这些修改后开工”属于对限定修改的批准，记录原消息、修改范围和最终稿哈希，不再重复索取同一审批。

## 3. 图片与事实对应

每个具体人物、地标、产品和可视事件优先使用可辨识图片/视频作为模块主体，文字用于身份、数值、因果/比较/时间关系。不得用大字号姓名或大方块标签代替人物/事件主体，不以无关库存照片填指标。每镜列实体→媒体→来源→用途；缺图继续找来源，确实无法获得则明确记录例外及替代解释方式供审稿。检查全片所有同类场景，不只修用户截图。

保留报纸、相片白边、胶带/图钉舞台；图片需在手机尺寸可辨，不能缩成角落装饰。只含文字的场景必须有语义理由（极短钩子、引语、必要数据/过渡），避免连续文字板。关系图用人物/机构/产品图片作为节点，短文字与箭头解释联系；不要默认重复套同一三框布局。

引用先展示完整身份（头像/作者/发布时间/正文，文件机构/日期/标题），再保持同一原图连续平移缩放至局部并高亮。优先取得主语言原件；仅有异语材料时保留原文，对正在讲的词句划词/高亮，并紧邻显示主语言译注，保持对应可见。不得把编辑翻译伪装成原帖或重新手绘证据。

## 4. 声音、制作与交付

读 audio-production.md；批准稿件后做所选音色的短试音，获确认后制作正式口播。实际音频决定时间线；独立旁白/SFX/BGM，再混音。逐镜审图片语义、语言、字幕、引用、进出场与声音同步；全片正常速度观看、真实听音分别留记录。机器通过不能代替听审。

README 展示只有完成新候选检查后才替换视频；旧版本标为历史/返修中，不能随着 Skill 发版宣称旧片已符合新规范。

## 可执行入口

`python3 scripts/preflight.py /path/review/production-brief.json` 检查声明选择、审稿状态和批准哈希。`project.py create /new/project --brief /path/review/production-brief.json` 通过后才复制模板；still/render 也检查项目 brief。直接调用 Remotion 可绕过包装器，所以 Agent 仍须遵守此流程；校验器不能认证用户消息真实性。

brief 最小结构：
```json
{"main_language":"en","subtitles":{"mode":"single","languages":["en"]},"language_choice_evidence":"用户原消息引用","voice_tool":"VoiceStudio","voice_choice_evidence":"用户选择引用","script_file":"script.md","script_review":{"status":"pass"},"script_approval":{"sha256":"实际已确认文件哈希","user_message":"真实批准消息引用"}}
```

## 1.9.4 来源与返修

所有归因句遵循 [来源生产合同](source-production-contract.md)，从原件核验到可见媒体绑定后才能完整渲染。口播与字幕禁用分号。实体条目核身份和素材出处并检查小屏辨识。读音返修须协调脚本、配音、字幕和声词锚点，并真实试听。时间线中的新闻/政府/X 归因必须列入 sourceClaimIds，不能因验证器无法自动识别语义而省略声明。
