# 从口播含义到动态画面（1.6）

先判断每句要观众理解什么，再选择视觉形式。人物、地点、具体事件需要真实形象；数量、规模、变化需要数据图；立场、因果、流程需要比较或关系动画；真实性需要原件和可读的重点。以整片完整叙事场景计数（排除品牌段），至少一半场景含有承担叙事作用、可清楚辨认的图片或视频；10个场景建议5–6个有图。不是每帧50%面积要求。不能用微小水印、纸纹、文件截图或拆碎场景来凑比例；人物/产品/机构的主体Logo可与关系或数据同场，图片负责辨认，图表负责分析，不虚构数据。

## 第一秒影像钩子

第一秒必须出现与话题直接相关的人物、产品或事件图片/视频，并开始有意义的入场/构图变化；前三秒让观众辨认主体与冲突。不能以纯文字、整页公告或静止文档作为开场。三国主题可用三位领导人依次进入的真实肖像拼贴，身份照片注明日期/来源，不能冒充三人共同出席或当天现场。肖像历史照片用于身份介绍，与把旧城市风貌当作当前事件素材不同；须明确影像用途。标题辅助影像，品牌仍在钩子之后。

## 可执行的镜头设计

在配音后写 `review-plan.json`：每个语义节点对应原句/词、实际声音时间、图片/数字/连接/高亮动作和阅读停留。用 ASR 或强制对齐取得词锚点，再抽听检查人名、数字和切换。句内等分只能标 estimated，不能声称精确对齐；未经检查的 estimated 不得用于关键事件切换。重复出现的人名、地点或词（例如 war / wars）必须按完整短语或词索引定位唯一位置；歧义匹配应报错，不能取第一个结果。禁止把历史照片或后一个事件提前贴出来。字幕变化、微缩放和背景纹理运动不算新的信息节点。

默认每 3–6 秒推进一项有意义信息，以实测语速为准。少于 1.5 秒连续大变化或超过 6 秒同信息停留都需要复核；原件阅读、单个重要数字和品牌可更长，写明阅读任务。不可为了通过频率检查增加无意义动作。动作约 0.3–0.6 秒，落稳后留阅读时间；同一时刻只突出一个主焦点。

### 数据比较

- 先研究问题：GDP 总量、实际增速、贸易额分别回答不同问题。不得用增速代表经济体量；不要把预测写成实绩。
- 同一比较用同指标、单位、时间和来源版本；写明名义/实际、币种、基期、预测/估计、检索日期。缺项先查证，不用无来源数值填画面。
- 柱状图共用刻度、从零开始；负数需显示零轴。折线图使用真实时间间隔与相同轴域，不用装饰折线冒充数据。变化量和排序只从同口径数据计算。
- 按说到的对象逐项揭示，数值与条长同步到终值。最后只在口播支持时显示差距或结论。保留数据清单及原始表/页码。
- `DataComparison` 接收明确的 `rows[].at`；没有默认逐行延迟。该组件是柱状图；折线图不是当前内置能力，需另行实现并验证。

### 图片与关系图

每个节点先确定对应的人、机构、产品或动作，能用真实形象说明的就配图片/主体Logo；具体事件图片仍遵守时效要求。关系图可以同时有图片、短标签和数据，不要把上一轮的“减少图片轮播”误解为“改成全部文字框”。

每条线必须能回答“从谁到谁、什么关系、是否有方向”。有向关系画箭头并标动作，无方向的比较明确标关系；并列三组关系不用一条竖线串成因果链。布局线、无含义主干、无端点短线一律删除。按源节点→目标节点→关系出现的次序呈现，检查动画中段不留下悬空误导连线。视觉检查必须核查关系含义，不能只看有没有溢出。

### 原文证据

先完整展示发布者、文件/帖子身份、日期和正文位置，再对同一张真实原图做连续平移与缩放。所有原文引用适用：先用细框定位重点，再用约0.4–1.5秒（默认0.8秒）的平滑摄影机运动，从原件全貌到对应局部；不能硬切或交叉淡化到另一张裁剪图。保留同一原图、同一坐标系与来源身份，观众应能追踪重点原来在页面哪里。即使截图是位图，运动须为连续坐标变换，无需把原文字重绘成矢量。用黄色马克笔依次划重点，旁边或下方用主语言大字说明“这是谁的文件、说明了什么”。摘要标为编辑摘要；外语原文按词句对照翻译，不改原图字词。不要让观众自己读整页小字；原件是可信度，放大与解释负责理解。

`EvidenceFocus` 的 crop/marks 使用原截图像素坐标，保留原件哈希。先整页、后连续摄影机变换、再高亮和摘要的帧必须来自配音节点。`focusAt`是缩放开始，`zoomFrames`默认24帧；高亮与摘要不得早于缩放落稳。定位框和黄笔共享原图变换，不能漂移。逐一检查开始、25%、50%、75%、结束帧；同源哈希只能证明来源，不能证明动画连续。手机宽 360px 下，主信息建议相当于 14–18px（1080画布42–54px）；原件小字可作出处全貌，但焦点关键句必须放大可读。看实际截图，不把字号配置当可读性证明。

### 素材时效

当口播描述具体时事时，素材必须匹配事件或对应时间，保存拍摄/发生日期；网页上传日期不能替代拍摄日期。2026年深圳会议不能用2016年城市照片，即使加 archive 标签也不能使它成为匹配素材。找不到当期图就改用真实公告、当期数据、地图/关系示意或省略该图。只有口播明确回顾历史时，才使用相符年代的历史图。一般背景图也要核对是否误导现状。

### 空间与时间检查

内容区建议 x=65–1015、y=360–1560；字幕与来源独立留区，不将标签或卡片边缘压到字幕中。按每个节点出现前、动画中间、落稳、最密集状态抽帧，并在 360px 预览检查。检查旋转后的四角、标签、时间线、黄笔、字幕和来源是否相互覆盖。元素碰撞、日期错配、关键素材提前出现必须修好，不能由平均分掩盖。

完整候选另外按正常速度看听，检查留白、节奏疲劳、同步、停顿和BGM干扰。记录候选 SHA、具体时间、所见/所听及修复；没有实际感知能力时明确列出未完成项。脚本、ASR、数值校验、抽帧、响度都不能替代完整视听验收。

## 固定频道 IP

SwainTalk 项目固定使用 `BrandLockup` 和 `public/brand/`。原透明 Logo 字节不变；slogan 固定为 `Follow the Tech, Follow the Money.`，视觉固定两行、Inter 700、44px/56px、Logo盒840×280、组合x120/y620、slogan相对top300。头尾使用同组件、同字体文件、同背景纸面、同入场动画。禁止文字替代Logo、黑色衬底、另加片名改变组合、每期换字体/位置/偏移；其他频道可另建独立品牌配置，不能修改SwainTalk锁定版本。

钩子之后才进入IP。品牌口播前后各留至少0.4秒无旁白区，结尾品牌前后也如此；BGM可低音量延续。连续原音中的口号须在自然句界切分/插停顿，重新核字幕、素材与音效时码，不能仅延长画面而让声音连读。整段复用同一读法优先；核对 Tech，避免误念 tag。完整时长以新混音为准，不能挤掉停顿或加速口播凑时长。

## 工具与审查边界

`python3 scripts/review_plan.py PROJECT/review-plan.json` 检查语义节点时间、关键声词锚点、数据口径、当前事件素材日期与品牌停顿记录。它验证制作记录，不能自动证明像素可读、真实声画同步或许可完备。新项目完整 render 必须有此计划；still 可先生成布局草稿。独立 Remotion 工程也需运行相同门禁。


实际停顿必须再运行 `python3 scripts/brand_pause_check.py PROJECT/review-plan.json PROJECT/VO.wav`。此检查需要 ffmpeg，读完整对齐的无BGM/无SFX旁白分轨，核对声明区间的样本峰值（−50 dBFS为本项目近静音检测阈值）和长度。先测再写PASS；ASR词尾不是音频文件尾，按词时间填静音记录可能仍包含发声。允许重采样的极低幅边缘残留，但不能把明显语音称为停顿。缺文件/缺工具不是PASS。

## 制作记录与 GIF 交付

1.6 完整渲染必须通过 `review_plan.py --require-visual`。在旧记录上增加：

- `visual_contract: "1.6"`；`scene_inventory` 完整覆盖时间线，每个场景记 `id/start/end/role`（content或brand）。每个实质图像记 `imagery:[{file,kind,purpose,substantial,from,until}]`，帧为全局帧、路径相对计划。kind可为photo/video/illustration/subject-logo；文件引用不计图片覆盖。按原始完整叙事场景统计，不以动画分步拆场景。
- `visual_hook:{scene_id,subject,image_at,motion_at,recognizable_by}`；首秒有实质影像及动作，90帧内可认主体（30fps）。实际检查首帧、0.5秒、1秒、2秒、3秒，不能仅填写记录。
- 每个原文全貌到局部都列入 `evidence_moves:[{id,file,sha256,whole_from,zoom_start,zoom_end,method:"same-source-transform",source_swapped:false,highlight_at,summary_at,review_frames}]`。review_frames至少记开始/中间/结束帧；文件hash须匹配。未发生局部放大则不需要伪造记录。
- 每张关系图列 `relationship_maps:[{id,nodes:[{id}],edges:[{from,to,label,direction}]}]`；direction是forward/both/none。记录所有实际线条，不能遗漏装饰主干。

GitHub README 不依赖内嵌 MP4 播放。每片从最终、已绑定hash的MP4挑3–5个3–5秒片段，覆盖钩子、证据连续放大、图片关系/数据分析；转成约270–320px宽、12fps的循环GIF。用Markdown图片直接展示，旁边给完整MP4下载/打开入口及封面、标题、描述、字幕、来源。保留片段起止秒、原视频SHA、GIF SHA的索引。GIF只展示动画，不是配音或全片验收；不要用旧版GIF代表新版。使用 `scripts/showcase_gifs.py` 从清单生成并验证每个片段。


1.9.4 的实体条目与折线图事件标记遵循 [Collage API](collage-api.md)。公司、人物和产品介绍逐项检查身份、真实图像来源及手机尺寸辨识，不以实体 Logo 代替报道原件。事件 marker 从横轴连至实际观测点，出现时刻对应口播，时序关联不证明因果；归因来源遵循 [生产合同](source-production-contract.md)。
